## 部署与使用边界

- 一个业务任务的创建、编辑与 Dify 回调必须连接同一后端和数据库；本机与云端两份 SQLite 不自动同步。
- 公网提供整个工作台前，先运行 `scripts/configure_access.py` 配置单操作人登录并启用 HTTPS；工具 Token 与登录凭证分别管理。
- 产品候选和图片来自已接入的知识库档案，不代表已覆盖所有可售 SKU。必用软件、系统及预算适配需要保留具体证据；没有可比报价时不声称提供了预算内最低价方案。
- 当前合规能力是规则与模型辅助检查；发现阻断项时限制正式复制/导出，并保留审核报告。没有宣称获得平台官方审核或法律合规认证。
- 没有执行公众号、小红书、朋友圈或商家账号的自动发布。输出由操作者检查后导出。
- `data/` 的任务、密钥配置和媒体属于私有运行数据，不进入 Git 或源码发布包；验收导出文件位于本机 `output/`，源码包不默认包含这些运行产物。

## 2026-10-20 保存需求修复

线上 Safari 在魔搭应用内保存需求时，原 PATCH 请求返回 HTTP 403（平台返回 `AccessDenied: unauthorized method 'PATCH'`）；失败提示位于模态框外，导致编辑窗口内看不到结果。brief 与 draft 增加同处理器的 POST 入口，前端统一使用 POST；原 PATCH/PUT 入口继续兼容。登录、来源白名单、任务归属和成品版本冲突检查沿用原处理流程。

保存期间在窗口内显示进度并阻止重复提交；失败时显示原因且保留输入，恢复连接后可重试。需求提交设置 30 秒超时。隔离本地浏览器已操作全字段保存、重开、刷新、取消、连接失败与恢复重试；`node tests/brief_flow.mjs` 覆盖慢请求、防重复、403重试、版本冲突和首次任务创建；登录四分支回归继续通过。云端已发布为 Running，用户刷新修复版后实际点击保存，确认“已保存，摘要已更新”。该结果验证需求保存操作，不扩大为全部云端控件已验收。
